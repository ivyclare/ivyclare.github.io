Examples (drawn from the wayback source):
   - `https://web.archive.org/web/20250617204937/https://twitter.com/IvolineNgong` → `https://twitter.com/IvolineNgong`

<nav_placeholder_handling>

For Phase 1, render the nav like this:
```
<nav aria-label="Site">
  <span aria-current="page">Main</span>
  · <span data-todo="phase-2">Papers</span>
  · <span data-todo="phase-2">Talks</span>
  · <span data-todo="phase-2">Code</span>
  · <span data-todo="phase-2">Writing</span>
</nav>
```

Why `<span>` not `<a href="...">`: Phase 1 has no `publications.html` / `talks.html` / `code.html` / `writing.html` files. A clickable `<a>` pointing at non-existent files would 404 — violating QUAL-03 (Phase 3). A `<span>` is unclickable and degrades gracefully. The `data-todo="phase-2"` attribute is a marker for Phase 2 (which will swap each span into `<a href="publications.html">Papers</a>` etc.).

Style: The `<span>` placeholders should look visually identical to inactive nav links (dark gray, no underline) so the nav appears complete. Plan 02's CSS rule `nav span` (if added) or simply default `color: var(--text-strong)` works; UI-SPEC's nav rules already handle this because `<span>` without a `color` declaration inherits the body color.

Active "Main" indicator uses `aria-current="page"` and styles via the existing `nav [aria-current="page"]` rule from Plan 02 (teal, no underline).

Middot separators (`·`) are rendered as plain text in the HTML between elements, flanked by spaces, matching UI-SPEC §Top navigation.
